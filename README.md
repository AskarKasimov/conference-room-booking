# Бронирование переговорных

Приложение для поиска свободных переговорных, просмотра расписания, создания и отмены своих бронирований

## Запуск

Команды выполняются из корня репозитория

### Docker Compose

```bash
cp .env.example .env
docker compose up --build
```

Приложение: [localhost:5173](http://localhost:5173), API: [localhost:3000](http://localhost:3000)

Для разработки с обновлением при изменении исходников:

```bash
docker compose -f docker-compose.dev.yml up --build
```

### Переменные окружения

| env | Смысл |
| --- | --- |
| `CLIENT_PORT` | Порт клиента на компьютере; по умолчанию `5173` |
| `VITE_API_BASE_URL` | Адрес REST API, доступный браузеру |
| `VITE_WS_URL` | Адрес WebSocket, доступный браузеру |
| `VITE_REQUEST_TIMEOUT_MS` | Таймаут запроса клиента в миллисекундах; по умолчанию `10000` |
| `SERVER_PORT` | Порт API на компьютере; по умолчанию `3000` |
| `CORS_ORIGINS` | Разрешённые адреса клиента для запросов к API |

Для запуска через npm клиентские переменные задаются в `client/.env`. Скопируйте `.env.example` в `client/.env`; параметры `VITE_API_BASE_URL` и `VITE_WS_URL` должны указывать на запущенный сервер

### npm

Нужен Nodejs 20.19+ и npm

В первом терминале запустите backend:

```bash
cd server
npm ci
npm run dev
```

Во втором - клиент:

```bash
cp .env.example client/.env
cd client
npm ci
npm run dev
```

Адреса приложения и API те же

Клиент читает настройки из `client/.env`: `VITE_API_BASE_URL` - адрес API, `VITE_WS_URL` - адрес WebSocket, `VITE_REQUEST_TIMEOUT_MS` - таймаут запросов. В примере уже указаны значения для локального запуска

## Тесты

Из корня репозитория:

```bash
npm --prefix client test
```

Клиентские тесты написаны на Vitest и Testing Library, запросы подменяются через MSW. Запускать backend для них не нужно. Проверяются правила бронирования, работа форм, маршруты, обработка конфликтов и WebSocket-событий

`npm --prefix client run test:watch` запускает тесты в режиме наблюдения. `npm --prefix client run check` проверяет форматирование, ESLint, типы, тесты и сборку

## Технологии и архитектура

- React 19 и TypeScript - интерфейс и типизация; Vite - сервер разработки и сборка
- React Router DOM - маршруты; TanStack Query - загрузка, кеширование и обновление серверных данных
- React Hook Form и Zod - формы и проверка данных
- Luxon - расчёт времени в часовом поясе офиса
- Radix UI и SCSS-модули - элементы интерфейса и стили
- WebSocket - обновление расписания и доступности комнат

Код клиента находится в `client/` и разделён по слоям Feature-Sliced Design:

- `app` - провайдеры, маршруты, WebSocket-соединение и глобальные стили
- `pages` - страницы, `widgets` - крупные блоки экранов
- `features` - выбор офиса, фильтры, создание и отмена бронирования
- `entities` - модели, API-запросы и отображение офисов, комнат, бронирований и пользователя
- `shared` - HTTP-клиент, общие компоненты, настройки и работа со временем

## Принятые решения

- Фильтры и дата расписания хранятся в URL, чтобы ссылкой можно было поделиться и пользоваться историей браузера. При переходе между разделами последний открытый адрес каждого сохраняется в памяти до перезагрузки страницы - это делает навигацию в веб-SPA более похожей на нативное приложение
- Время отображается и проверяется в часовом поясе выбранного офиса, чтобы результат не зависел от настроек компьютера пользователя
- После успешного создания или отмены бронирования клиент сразу обновляет кэш TanStack Query: добавляет новую бронь в подходящие списки и расписание либо удаляет отменённую. Кэш комнат инвалидируется, чтобы обновить доступность
- После WebSocket-событий клиент повторно запрашивает затронутые данные через REST. При потере связи показывает уведомление и переподключается; после восстановления соединения обновляет данные, чтобы учесть пропущенные события
- При конфликте `409` форма сообщает, что время уже занято, а клиент обновляет расписание и доступность комнат
